# CRUD Map: PARSU Student Appointment and Queue Management System

The system uses seven tables. A dash means deletion is intentionally restricted because the record is needed for history, reporting, or referential integrity.

## 1. Table-to-page CRUD map

| Table | Create | Read | Update | Delete | Pages | Who can do it? |
|---|---:|---:|---:|---:|---|---|
| `students` | ✓ | ✓ | ✓ | – | `register.php`, `profile.php`, `admin/students.php` | Student creates and updates own profile; staff read identity; admin reads/updates. No delete: appointment history must remain linked. |
| `staff` | ✓ | ✓ | ✓ | – | `admin/staff-form.php`, `admin/staff-list.php` | Admin only. No delete: deactivate with `is_active` so review history remains attributable. |
| `offices` | ✓ | ✓ | ✓ | – | `office-list.php`, `office-view.php`, `admin/office-form.php` | Everyone reads active offices; admin creates/updates/deactivates. No delete: services and appointments retain office history. |
| `services` | ✓ | ✓ | ✓ | – | `service-list.php`, `service-view.php`, `admin/service-form.php` | Students/staff read; admin creates/updates/deactivates. No delete: appointment history references services. |
| `schedules` | ✓ | ✓ | ✓ | – | `service-view.php`, `appointment-form.php`, `staff/schedule-form.php` | Staff/admin create and update; students read open schedules. No delete: close a schedule instead of removing it. |
| `appointments` | ✓ | ✓ | ✓ | – | `appointment-form.php`, `appointment-list.php`, `appointment-view.php`, `staff/appointments.php` | Student creates and reads/updates own pending request; staff reads and updates status; no delete—cancel instead to preserve audit history. |
| `queue_entries` | ✓ | ✓ | ✓ | – | `queue.php`, `appointment-view.php`, `staff/queue.php` | Staff creates/updates when confirming and serving; student reads own queue. No delete: queue history supports accountability. |

## 2. Important table field lists

### `appointments` — main form table

| Column | MySQL type | HTML control | Required? | Notes |
|---|---|---|---|---|
| `appointment_id` | `INT AUTO_INCREMENT` | No field on Add | No | Generated by MySQL; hidden on Edit if needed. |
| `student_id` | `INT` foreign key | Hidden/current-user value | Yes | PHP derives this from the authenticated student. |
| `service_id` | `INT` foreign key | Select dropdown | Yes | Show `services.service_name`; submit the service ID. |
| `schedule_id` | `INT` foreign key | Select/radio cards | Yes | Show date/time and remaining capacity; submit the schedule ID. |
| `purpose` | `TEXT` | Textarea | Yes | Explain the request; server validates length. |
| `status` | `ENUM` | No field on student Add; select for staff | Yes | Values: `pending`, `confirmed`, `serving`, `completed`, `cancelled`. |
| `reviewed_by` | `INT` foreign key | No field on student Add | No | Staff/admin ID added during review. |
| `created_at` | `DATETIME DEFAULT CURRENT_TIMESTAMP` | No field | No | Generated by MySQL. |

### `queue_entries` — queue control table

| Column | MySQL type | HTML control | Required? | Notes |
|---|---|---|---|---|
| `queue_id` | `INT AUTO_INCREMENT` | No field | No | Generated by MySQL. |
| `appointment_id` | `INT UNIQUE` foreign key | Hidden/current appointment | Yes | Created only for a confirmed appointment. |
| `queue_number` | `INT` | Number input | Yes | Staff assigns the next number for that office/date. |
| `called_at` | `DATETIME` | `datetime-local` or no field | No | Set when staff calls the student. |
| `completed_at` | `DATETIME` | `datetime-local` or no field | No | Set when service is completed. |

## Schema changes

- **Added:** `queue_entries` to keep queue numbers and timestamps separate from appointment requests; `reviewed_by` on `appointments` to identify the staff reviewer.
- **Removed:** None.
- **Renamed:** None.
- **Reason:** The existing static concept displayed queue numbers and staff review states, so the database needs explicit structures for both in Week 15.
